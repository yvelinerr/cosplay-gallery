# 开发日志

从下一次开发任务开始，每个任务在此目录创建独立子文件夹，命名为 `dev` + 数字 + 任务名称，例如 `dev1图集搜索优化`。编号从 1 起递增，取现有最大编号加 1；同一任务断联后续做时复用原目录。

| 文档 | 职责 |
| --- | --- |
| `plan.md` | 整体规划：目标、范围、实施方案、阶段、依赖及验收标准 |
| `task.md` | 细分任务清单、完成情况、当前步骤、下一步、阻塞及验证结果 |
| `context.md` | 用户需求、限制、相关文件、接口、决策、环境与恢复所需上下文 |

**每完成一项细分任务，立即更新并保存 task.md，再开始下一项；不得在任务结束时批量补记。** 当前步骤、阻塞或验证结果变化时也立即更新。断联恢复后先阅读三文档，再核对实际文件与 Git 差异，继续未完成项。

开发日志应提交到版本控制，不能包含令牌或敏感信息。新建任务及更新状态时同步维护 [Index.md](../Index.md)。完整规则以 [AGENT.md](../AGENT.md) 为准。

本次仅建立规则与目录，按用户要求不创建任务子文件夹；首个后续任务使用 `dev1任务名称`。
